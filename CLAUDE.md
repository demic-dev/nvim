# Code style

- Never overengineer. Write the simplest thing that solves the problem asked, nothing more.
- Never overabstract. No layers, wrappers, or indirection added "for the future" — abstract only when there is a concrete, present need.
- Comments only when necessary, and never verbose. Explain *why* when it isn't obvious; never restate what the code already says.
- Prefer clear, intuitive code over comments. If a comment is needed to explain what code does, rewrite the code instead.
- Write comments and documentation in Standard Technical English, rigorously: precise terminology, complete declarative sentences, no colloquialisms, hedging, or filler.
